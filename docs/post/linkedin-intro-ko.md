## 본문

로컬에서 도는 오픈소스 모델로 쿠버네티스 플랫폼을 어디까지 자동화할 수 있을까요?

GitAIOps 실습서의 스택(GitOps · 관측성 · 무중단 배포 · 멀티테넌시)을
**온프렘 + 로컬 Qwen**으로 다시 세워보고, 쉬운 것과 어려운 것을 정리했습니다.
맥북 한 대, 클라우드 API 없음, 비용 0원.

**쉬웠던 것**
자연어 한 문장이 클러스터 생성 → 배포 → 검증까지 **39초**.
로그 보고 장애 원인 짚기(OOMKilled, confidence 0.95).
카나리 배포 자동 판정 — 크래시 나는 배포를 **165초 만에 롤백**.

**의외였던 것**
라우팅 정확도 20개 케이스 측정에서 **7B가 30B를 이겼습니다**(20/20 vs 19/20, 게다가 더 빠름).
temperature를 올리면 나빠지고요. 인프라 작업에 창의성은 필요 없더군요.
그리고 정확도 80% → 100%를 만든 건 모델 교체가 아니라 **프롬프트 한 문단 수정**이었습니다.
네 가지 설정이 전부 같은 케이스를 틀렸는데, 원인은 제가 프롬프트에 잘못 쓴 정의였습니다.

**어려웠던 것**
되돌릴 수 없는 조치, 다른 자동화와의 충돌(에이전트가 롤백하면 ArgoCD가 40초 뒤 원복),
그리고 제일 어려운 **"에러가 안 나는 실패"**.
쿼터를 네임스페이스마다 걸면 팀 전체로는 4배가 되는데 화면엔 정상으로 보이고,
보안 정책을 켜니 정작 제 로그 수집기가 거부됐는데 ArgoCD는 "동기화 완료"에 파드는 0개였습니다.
LLM은 여기서 도움이 안 됩니다. 에러 메시지가 없으니 물어볼 것도 없거든요.

**결론**
자동화는 러닝커브를 없애지 않고 **앞으로 당깁니다.**
나중에 열 번 겪을 걸 처음에 한 번 제대로 겪게 만듭니다.
반복 비용은 줄지만, 학습 비용은 오히려 늘어요.
손으로 할 땐 에러 보고 고치면 되지만, 자동화는 에러가 안 나는 실패까지 다뤄야 하니까요.

수치와 실전 팁(7B로 충분한 이유, 툴 콜이 안 붙을 때, 실습서 항목별 대조표)은 전문에 정리했습니다.
