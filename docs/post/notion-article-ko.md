# 로컬 Qwen으로 쿠버네티스 플랫폼 자동화, 어디까지 쉬울까

GitAIOps 실습서(GKE 기준)의 스택을 **온프렘 + 로컬 Qwen**으로 다시 세워보고,
어디까지 쉽게 되고 어디서부터 어려운지 정리했다.

전부 맥북 한 대에서 돌렸다. 클라우드 API 없음, 인터넷 없음, 비용 0원.
아래 수치는 전부 실측이다.

---

## 한눈에

| | 결론 |
|---|---|
| 쉬운 것 | 자연어 → 도구 호출, 로그 요약·원인 추정, 정형 판정 |
| 준비하면 되는 것 | 툴 콜 정규화, 프롬프트 정합, 추론 속도 |
| 어려운 것 | 되돌릴 수 없는 조치, 다른 자동화와의 충돌, **에러가 안 나는 실패** |
| 모델 크기 | **7B로 충분.** 30B보다 빠르고 정확했다 |

---

## 1. 쉬운 것 — 생각보다 바로 된다

### 자연어 → 실제 작업

> "온프렘 클러스터 만들고 orders-api 배포한 뒤 정상인지 확인해줘"

이 한 문장이 클러스터 생성 → 배포 → 검증까지 **39초**에 끝난다.
어려운 축에 속할 거라 생각했는데 제일 먼저 된 부분이었다.

**왜 쉬운가**: 이 작업의 본질은 "문장에서 의도와 파라미터를 뽑아 정해진 함수를 부르는 것"이다.
경우의 수가 유한하고 출력 형식이 고정돼 있다. 로컬 모델이 잘하는 영역이다.

### 라우팅 정확도: 7B가 30B를 이겼다

20개 케이스(적대적 5개 포함)로 측정했다.

| 모델 | temperature | 정확도 | 응답 |
|---|---|---|---|
| **Qwen2.5-Coder-7B** | 0 | **20/20** | 0.20초 |
| Qwen3-Coder-30B | 0 | 19/20 | 0.22초 |
| Qwen2.5-Coder-7B | 1.0 | 18/20 | 0.23초 |
| Qwen3-Coder-30B | 1.0 | 19/20 | 0.24초 |

두 가지가 보인다. **크기를 4배 키워도 나아지지 않았고, temperature를 올리면 나빠졌다.**
인프라 작업에 창의성은 필요 없다. 실제로 이 프로젝트는 30B로 시작했다가 7B로 내렸다.

### 로그 보고 원인 짚기

파드가 OOMKilled로 죽었을 때 로컬 모델이 **confidence 0.95로 정확한 원인**을 짚었다.
"메모리 리밋이 부족하다"까지 근거와 함께 나온다.

### 정형 판정

카나리 배포 중에 "괜찮다 / 문제다 / 모르겠다"를 반복 판정시켰다.
크래시 나는 배포를 **165초 만에 자동 롤백**시켰고, 정상 배포는 통과시켰다.
판정 1회 2.8초, 근거 신호가 없을 땐 0초(모델을 안 부른다).

---

## 2. 준비하면 되는 것 — 알고 시작하면 덜 헤맨다

### 툴 콜이 그대로는 안 붙는다

Qwen3-Coder는 함수 호출을 `<function=...>` 형태로 뱉는데,
MLX 서버 파서가 기대하는 `<tool_call>` 마커가 빠질 때가 있다.
그러면 클라이언트(LangChain·Pydantic AI 등)가 툴 콜을 인식하지 못한다.

해결은 간단하다. **응답을 OpenAI 표준 형식으로 정규화하는 프록시**를 하나 끼우면 된다.
로컬 200줄 정도. 모델을 바꾸거나 파인튜닝할 문제가 아니다.

> 실전 팁: "로컬 모델은 툴 콜이 안 된다"는 말을 종종 보는데,
> 대개 모델 능력이 아니라 **출력 포맷 파싱** 문제다.

### 모델보다 프롬프트가 먼저다

처음엔 라우팅 정확도가 80%였다. 네 가지 설정이 **전부 똑같은 두 케이스**를 틀렸다.

- "terraform apply 왜 실패했는지 조사해줘" → 진단이 아니라 프로비저닝으로 분류
- "스테이징 클러스터 내려줘" → 배포가 아니라 프로비저닝으로 분류

모델 한계인 줄 알았는데, 프롬프트에 프로비저닝을 "인프라를 **만들거나 내리는** 것"이라고
써놓은 게 원인이었다. 모델은 프롬프트를 정확히 따랐고, **틀린 쪽은 프롬프트였다.**

한 문단 고치니 80% → **100%**. 모델 크기를 4배 키우는 것보다 훨씬 큰 개선이었다.

> 실전 팁: 여러 모델이 **같은 케이스**를 틀리면 모델이 아니라 프롬프트를 의심할 것.

### 느린 건 쿠버네티스가 아니라 추론이다

장애 대응 전 과정을 추적해보면:

```
전체 5,026ms 중 → 분석(로컬 추론) 4,136ms = 82%
```

나머지 감지·판단·실행을 다 합쳐도 18%다.
체감 속도를 올리고 싶으면 손댈 곳은 하나뿐이고, 그게 7B를 고른 이유이기도 하다.

## 3. 어려운 것 — 모델을 바꿔도 안 풀린다

### 되돌릴 수 없는 조치

모델 정확도와 **무관하게** 사람 승인이 필요한 영역이 있다.
그래서 자동 실행은 되돌릴 수 있는 4가지로 제한했다 —
파드 재시작, 이전 버전 되돌리기, 스케일 조정, 노드 드레인(강제 옵션 없이).

디스크 확장이나 인증서 갱신은 알람에 없는 정보가 필요하다. 추측하면 사고다.

**판단 기준은 "모델이 얼마나 정확한가"가 아니라 "틀렸을 때 되돌릴 수 있는가"다.**

### 다른 자동화와 충돌한다

GitOps는 클러스터를 선언된 상태로 계속 되돌린다.
그래서 에이전트가 롤백해도 **40초 뒤 ArgoCD가 다시 원복시킨다.**
복구 루프와 배포 루프가 서로 싸우는 상태다.

이건 모델 문제가 아니라 **시스템 설계 문제**다.
"누가 최종 결정권자인가"를 정하지 않으면 자동화 둘이 서로를 되돌린다.

### 에러가 안 나는 실패 (제일 어렵다)

자동화하면서 만난 문제 대부분이 이 종류였다. 전부 화면상으로는 정상이다.

- **쿼터**: 한 팀이 네임스페이스 4개를 쓸 때 각각에 "16코어"를 걸면 팀 전체로는 **64코어**가 된다.
  화면엔 16이라고 표시된다. 조용히, 관대한 방향으로 틀린다.
- **보안 정책**: "루트 금지"를 켜자 정작 로그 수집기가 거부당했는데,
  ArgoCD는 "동기화 완료"에 파드는 0개였다. 진짜 이유는 세 단계 아래 이벤트 로그에 있었다.
- **삭제**: 애드온을 지웠더니 로그 데이터 볼륨까지 같이 사라졌다.
  쿠버네티스 기본값은 보존인데 그 차트가 뒤집어놨던 것이다.
- **소비되지 않는 코드**: 네트워크 정책 차트를 만들어놨는데 그걸 설치하는 코드가 없었다.
  테스트는 전부 초록이었다.

**LLM은 여기서 아무 도움이 안 된다.** 에러 메시지가 없으니 물어볼 것도 없다.
직접 돌려보고, 실제로 소비해보는 수밖에 없다.

> 실전 팁: 정지 상태 조회는 거짓말을 한다.
> 쿼터가 제대로 걸렸는지는 **실제로 자원을 써봐야** 알 수 있다.

## 4. 실습서 대비 어디까지 왔나

| 실습서 (GKE, 수동) | 온프렘 + Qwen |
|---|---|
| 클러스터 · 빌드 · 배포 | ✅ 자연어 39초 |
| GitOps (ArgoCD) | ✅ drift 16초 자동 복원 |
| 메트릭 · 로그 · 트레이스 | ✅ 3종 |
| 알림 | ✅ + 에이전트 파이프라인 연결 |
| 무중단 배포 (Canary) | ✅ + 모델 판정 자동 롤백 |
| CronJob | ✅ |
| 멀티테넌시 | ✅ 실습서(네임스페이스+RBAC)보다 확장 |
| Gateway API | ❌ Ingress로 대체 |
| 캐시 · 메시징 | ❌ 앱 레이어라 범위 밖 |
| 시크릿 관리 | ❌ 미완 |
| 멀티 노드풀 | ❌ 노트북에선 의미 없음 |

멀티테넌시는 네임스페이스 분리를 넘어 **쿼터·네트워크·권한·파드보안 4축**을 붙였다.
git에 팀 정보 한 줄 쓰면 전부 자동 생성되고, 테넌트를 통째로 지운 뒤 git만으로 복구되는 것도 확인했다.

---

## 정리 — 러닝커브는 줄지 않는다, 옮겨간다

**반복 비용은 확실히 준다.** 팀 추가는 git 한 줄, 서비스 배포는 39초.
실습서 챕터를 다시 밟을 일이 없다.

**학습 비용은 오히려 는다.** 쿼터를 자동 생성하려면 쿼터가 어떻게 합산되는지 알아야 하고,
보안 정책을 켜려면 어떤 파드가 왜 거부되는지 알아야 한다.
손으로 할 땐 에러 보고 고치면 되지만, 자동화는 **에러가 안 나는 실패**까지 다뤄야 한다.

> 자동화는 러닝커브를 없애지 않는다. **앞으로 당긴다.**
> 나중에 열 번 겪을 것을 처음에 한 번 제대로 겪게 만든다.

손해는 아니다. 열 번보다 한 번이 낫고, 그 한 번이 코드로 남으면 다음 사람은 안 겪는다.
다만 "AI로 자동화하면 쉬워지겠지"를 기대하고 시작하면 초반에 당황할 것이다.

### 시작한다면 이 순서

1. **7B + temperature 0** 으로 시작. 크기부터 키우지 말 것
2. **툴 콜 정규화 프록시** 먼저 확인 (모델 탓하기 전에)
3. 여러 모델이 같은 케이스를 틀리면 **프롬프트를 고칠 것**
4. 자동 실행은 **되돌릴 수 있는 것부터**
5. 배선이 끝나면 **반드시 실제로 돌려볼 것.** 테스트는 초록인데 안 도는 코드가 나온다

---

*검증 환경: 로컬 kind 클러스터, 실 사용자 트래픽 없음, 테넌트 2개.
자동 롤백은 GitOps 충돌 때문에 기본 비활성.*
