# 30초 영상 시나리오 (LinkedIn 첨부용)

목적: 스크롤을 멈추게 하고, "이게 진짜 돌아가네"를 **말이 아니라 화면**으로 보여준다.
30초 안에 설명까지 하려 들면 셋 다 실패한다. **장면 하나만** 고른다.

## 공통 원칙

- **소리 없이 이해되게.** LinkedIn은 대부분 음소거로 본다. 자막이 곧 내레이션이다.
- **자막은 한 컷에 한 줄, 6단어 이내.** 읽을 시간을 준다.
- **커서·타이핑을 보여준다.** 사람이 치는 화면이 편집 영상보다 신뢰가 간다.
- **배속은 쓰되 숨기지 않는다.** 화면 구석에 `×4` 또는 `39초 → 8초 압축` 표기.
  실제 시간을 속이면 나머지 주장도 같이 의심받는다.
- **첫 3초에 결과의 실마리**를 보여준다. 로딩 화면으로 시작하면 이탈한다.

---

## 시나리오 A — "한 문장 → 39초" (추천)

가장 직관적이고 설명이 거의 필요 없다. 처음 올리는 영상이면 이걸 권한다.

| 시간 | 화면 | 자막 |
|---|---|---|
| 0–3s | 빈 터미널에 한 문장이 타이핑됨<br>`"온프렘 클러스터 만들고 orders-api 배포한 뒤 정상인지 확인해줘"` | **자연어 한 문장** |
| 3–6s | 엔터 → 계획 단계 출력(도구 4개 나열) | 맥북에서 도는 Qwen이 계획을 세운다 |
| 6–16s | 클러스터 생성 → 배포 로그 흐름 (×4 배속, 우측 상단에 경과 타이머) | 클러스터 생성 · 배포 · 검증 |
| 16–22s | `kubectl get pods` → `orders-api  1/1  Running` | **39초** |
| 22–27s | 화면 분할: 좌측 "인터넷 연결 없음", 우측 "비용 $0" | 클라우드 API 없이, 오프라인으로 |
| 27–30s | 정지 화면 + 한 줄 | 쉬운 건 여기까지. 어려운 건 따로 있다 → 전문 링크 |

마지막 자막이 중요하다. **자랑으로 끝내지 않고 글로 넘긴다.**

---

## 시나리오 B — "격리 증명" (임팩트는 제일 큼)

멀티테넌시를 다루므로 아티클 본문과 가장 잘 붙는다. 다만 상황 설명이 필요해 3초쯤 더 든다.

| 시간 | 화면 | 자막 |
|---|---|---|
| 0–4s | 네임스페이스 목록: `acme-dev-*` 4개, `globex-dev-*` 1개 | 한 클러스터, 두 팀 |
| 4–10s | acme 파드 → acme 서비스 접속 시도 → 성공 | 같은 팀: 통과 |
| 10–17s | globex 파드 → acme 서비스 접속 시도 → **타임아웃/거부** | 다른 팀: 차단 |
| 17–23s | 라벨을 acme로 바꿔 우회 시도 → 라벨이 되돌아옴 | 라벨을 바꿔도 되돌아온다 |
| 23–27s | git의 팀 선언 파일 한 화면 | 이 전부가 git 한 줄에서 생성됨 |
| 27–30s | 정지 + 링크 | 네임스페이스 분리만으로는 안 막힌다 |

17–23초 구간(우회 시도 실패)이 이 영상의 핵심이다. 없으면 그냥 방화벽 데모로 보인다.

---

## 시나리오 C — "AI가 배포를 막는다" (설명 부담 큼)

카나리 자동 롤백. 실제 165초라 30초로 압축하면 배속이 커지고, 카나리 개념을 모르면 안 와닿는다.
**세 번째 영상으로 미루는 것을 권한다.**

| 시간 | 화면 | 자막 |
|---|---|---|
| 0–5s | 새 버전 배포 시작, 트래픽 일부 전환 | 새 버전을 일부에게만 |
| 5–12s | 파드가 CrashLoop로 죽기 시작 | 새 버전이 죽는다 |
| 12–20s | 판정 로그 `pass → fail → fail` (×8 배속) | 모델이 판정한다 |
| 20–26s | 자동 abort, 기존 버전 4/4 유지 | **165초, 사람 개입 0** |
| 26–30s | 정지 + 링크 | 기존 버전은 그대로 |

---

## 추천

**A로 시작한다.** 이유:

- 30초에 들어가고, 설명이 필요 없고, 결과가 한 줄로 떨어진다(`1/1 Running`)
- 아티클의 도입부와 정확히 같은 장면이라 링크 연결이 자연스럽다
- 실패 위험이 가장 낮다(재촬영이 쉽다)

여유가 되면 **A 뒤에 B의 10–17초 구간(다른 팀 차단)을 3초만 붙이는 하이브리드**도 좋다.
"띄우는 것"과 "격리하는 것"을 한 영상에 담을 수 있다. 단 30초를 넘기지 말 것.

## 촬영 전 체크리스트

- [ ] **MLX 모델을 7B로 내린다.** 30B는 첫 응답이 느려 화면이 빈다.
      `MLX_MODEL=mlx-community/Qwen2.5-Coder-7B-Instruct-4bit`
- [ ] **워밍업 1회 실행.** 첫 호출은 모델 로드 때문에 수십 초 걸린다. 촬영은 두 번째부터.
- [ ] `make dev-up` 후 전 포트 확인 (MLX · 라우터 · 웹훅 · 대시보드)
- [ ] kind 클러스터를 **깨끗한 상태로** 시작 (이전 실험 잔여물이 화면에 보이면 산만하다)
- [ ] 터미널 폰트 16pt 이상, 다크 테마, 창 폭 100컬럼 내외 (모바일에서 읽혀야 한다)
- [ ] 화면 녹화는 **세로 또는 정사각(1:1)** — LinkedIn 피드에서 세로가 유리하다
- [ ] 알림·슬랙·개인 정보 창 정리
- [ ] 실제 소요 시간을 따로 기록해둔다 (자막 수치는 실측이어야 한다)

## 편집

- 대기 구간만 배속하고, **결과가 나오는 순간은 등속**으로 둔다
- `1/1 Running` 같은 결정적 프레임은 1초 이상 고정
- 마지막 3초는 정지 화면 + 링크 (재생이 끝나도 정보가 남는다)
- BGM 없이도 성립하게 만들 것. 넣더라도 볼륨은 낮게
