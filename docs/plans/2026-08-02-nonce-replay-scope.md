# 조사 — attested approval의 nonce는 one-time-use가 아니다

조사일: 2026-08-02 · gate 1608 기준 · **truth-fix는 실행함, 집행 방식은 미결**

> 결론 요약: `AttestedApproval.nonce`는 *"One-time-use marker; the broker rejects a replayed
> nonce"*라고 적혀 있었다. **프로덕션에서 한 번도 거부한 적이 없고**, 게다가 **지금 켜면 정당한
> 호출자를 깨뜨린다.** 앞의 절반은 고쳤고(주장을 사실로 + 가드), 뒤의 절반은 **"1회란 무엇인가"**를
> 정해야 하는 설계 결정이라 남긴다.

---

## 1. 어떻게 발견했나

Phase 5(레지스트리 PR 쓰기)를 다음 우선순위로 잡고 실체를 재보니 **완전 그린필드**였다
(CODEOWNERS 0 · PR 생성 seam 0 · 대시보드 attach-addon UI 0). 설계 문서상 Phase 4·5는 둘 다
**(선택)**이다. 반면 `NEXT_PLAN` **2차 잔여**에 "서명키 custody·rotation — **결정 5-A의 선행**"이
있는데 **5-A는 이미 출하됐다**(D38). 선행이 안 끝난 채 출하된 항목이 선택 항목보다 앞이라 판단해
그쪽을 측정하다가, 서명키가 아니라 **재사용 방지 쪽**에서 구멍이 나왔다.

(서명키 자체는 **거짓 주장이 아니었다** — `Makefile:256`이 *"Local development only… NOT a
secret-management story"*라고 정확히 라벨해 두었다. 그 전제는 깨지지 않았다.)

## 2. 측정

### ① 프로덕션 경로로 3회 재제출 → 3회 발급

```
동일한 attested 레코드를 프로덕션 경로로 3회 제출 (nonce = one-time-use 선언):
  시도 1: MINTED  tenant=acme
  시도 2: MINTED  tenant=acme
  시도 3: MINTED  tenant=acme
```

원인: `TokenBroker._spent`는 **인스턴스 속성**인데, 유일한 프로덕션 호출자
`resolve_incident_scope`(`scope.py:379`)가 **호출마다 `TokenBroker.from_env(...)`를 새로 만든다.**
매번 빈 set이니 `mint`의 재사용 검사는 언제나 통과한다.

### ② 테스트는 내내 초록이었고, **그 테스트가 유일한 성립 조건을 제공했다**

`tests/test_incident_scope.py::test_nonce_replay_is_refused`는 `broker` 픽스처 **하나**를 잡고
`mint`를 두 번 부른다. 프로덕션에 없는 수명을 테스트가 만들어 준 것이다. 이번 계열에서 **수호
테스트가 홀을 놓친 게 아니라 홀을 가린** 첫 사례다.

### ③ 그리고 지금 켜면 **정당한 호출자가 깨진다**

`src/agents/operations/aws/executor.py`는 같은 인시던트에 대해 스코프를 **두 번** 해석한다 —
런북 경로(`:172`)와 액션 경로(`:253`). 여기에 Step Functions 재시도가 겹치면 더 늘어난다.
즉 진짜 one-time-use는 **정상 실행을 거부**한다. 그래서 이건 "`_spent`를 영속화하자"가 아니라
**"1회의 단위가 무엇인가"** 문제다.

## 3. 영향 범위 — 정직하게

**테넌트 경계는 깨지지 않는다.** 서명이 `approval_id·tenant·env·nonce`를 덮으므로 재사용해도
**같은 테넌트의 같은 스코프**가 다시 나올 뿐이고, 남의 테넌트로는 못 넘어간다(가드에 단언으로
고정함). 무너지는 것은 **감사 주장**이다: "이 승인은 정확히 한 번의 행동을 인가했다"가 사실이
아니다. 승인 하나로 몇 번이든 자격증명을 다시 얻을 수 있고, 그 행동들은 전부 **옛 `approval_id`로
귀속**된다.

## 4. 이번에 실행한 것 (모호하지 않은 절반)

레포 규약: **집행하지 않는 것을 광고하지 말 것.**

- `AttestedApproval.nonce` 주석에서 "one-time-use" 주장 제거 → 측정된 사실로 교체.
- `TokenBroker._spent`에 **왜 안 되는지 + 켜면 왜 깨지는지**를 기록.
- `mint`의 검사에 "인스턴스 안의 tight loop만 막는다"고 명시.
- 기존 테스트 이름 `test_nonce_replay_is_refused` →
  `test_nonce_replay_is_refused_within_one_broker_instance`(이름이 주장이었다).
- 새 가드 `tests/test_scope_replay_reachability.py` — **프로덕션 함수로** 단언한다. 재사용이
  실제로 거부되기 시작하면 **일부러 red가 되게** 썼다(그때는 동작이 바뀐 것이므로 주석·계획·
  테스트가 함께 움직여야 한다). 테넌트 불변("재사용해도 남의 테넌트는 안 나온다")도 함께 고정.

## 5. 남은 결정 — "1회"의 단위

| 안 | 내용 | 대가 |
|---|---|---|
| **A. 인시던트 1회** | nonce를 `(approval_id)` 단위로 보고, **해석은 여러 번 허용하되 결과를 캐시**한다(같은 인시던트면 같은 스코프 재발급). 영속 저장 불필요. | 재사용 공격도 "같은 인시던트"로 보이면 통과 — 감사 주장은 여전히 약함 |
| **B. 행동 1회** | `(approval_id, action)`을 소비 단위로 하고 **영속 저장**(실행기 쪽 스토어에 조건부 쓰기). 진짜 one-time-use. | 클라우드마다 스토어가 달라 **어댑터 3종**에 새 의존성 · 재시도 시맨틱 재설계 |
| **C. 만료로 대체** | 재사용 대신 **짧은 TTL**을 서명에 넣어 오래된 승인을 거부. | 창 안에서는 재사용 가능 — 약속을 줄이는 대신 지킬 수 있는 약속 |

**추천: C → (필요해지면) B.** 이유: 지금 새로 만들 수 있는 정직한 보증은 "오래된 승인은 못 쓴다"
쪽이고, 그건 스토어 없이 서명만으로 집행된다. B는 **실행기 3종에 상태 저장을 새로 도입**하는
일이라 Phase 4(managed 어댑터)와 함께 결정하는 게 맞다. A는 겉보기 개선인데 감사 주장을 되살려
주지 못해 **다시 광고 위반**이 될 소지가 있다.

**지금 열지 않은 이유**: TTL 길이도, 소비 단위도 **정책 결정**이고, 이 레포는 정책을 발명하지
않는다(analyzer severity 매핑을 남겨 둔 것과 같은 이유). `NEXT_PLAN`에 열린 항목으로 남긴다.
